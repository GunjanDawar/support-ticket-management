# Documentation Guidelines

## General

Documentation should explain the system clearly enough for another developer
to understand and maintain it.

## Specifications

Specifications must describe:

- Requirements
- Architecture
- Data model
- API contract
- State machine
- UI flow
- Test strategy

## Code Documentation

Document:

- Non-obvious business rules.
- Important architectural decisions.
- Complex algorithms.
- Important trade-offs.

Avoid comments that simply repeat what the code already says.

## Architecture Documentation

Architecture documentation should explain:

- Major components.
- Responsibilities.
- Communication between components.
- Persistence.
- Error handling.
- Important design decisions.

## AI-Generated Changes

When AI makes a meaningful engineering suggestion that is rejected or corrected,
document the decision where appropriate.

## README

README should contain:

- Project overview.
- Technology stack.
- Architecture.
- Setup instructions.
- Running instructions.
- Testing instructions.
- SDD workflow.
- AI-assisted development approach.
- Important engineering decisions.
- Known limitations.
